# Jevlike 계열의 기억 판단 활용 연구

작성: Codex, 2026-10-14 KST. 대상: rsch R05·R06 기억 관계 연구. 상태: 공개 문서·코드와 기존 기억 사례에 근거한 적용 제안. 우리 기억 데이터의 모델 성능은 아직 측정하지 않았다.

후속 실행: 사용자의 소규모 테스트 지시에 따라 [첫 로컬 시험 결과](MEMORY_PILOT_RESULTS_CODEX.md)를 추가했다. Kev 0.8B의 기본 36문항은 검토 전 제안과 17개 일치했고, 선택지 역순 12문항 중 3개가 바뀌었다. 아래 내용은 실행 전의 적용 가설이며 현재 실측은 후속 결과를 따른다.

Jevlike 계열은 반복되는 의미 관계 판단을 맡는 작은 분류기로 쓸 가능성이 있다. 표현이 다른 두 기억의 공통 주장과 새 조건을 찾아 관계 후보를 만들고, 어려운 건만 상위 검토로 보내는 용도다. 효용은 분류 정확도 하나보다 **허용한 오류 수준에서 처리할 수 있는 비율, 줄어든 큰 모델 호출과 검토량, 유지 비용**으로 판단해야 한다.

현재 검토한 vinnylarouge/jevlike는 바로 쓸 기억 전문가가 아니라 학습용 출발점이다. 사전학습된 Kev, 다국어 NLI, 짧은 구조화 출력을 쓰는 일반 LLM을 같은 기억 사례에서 먼저 비교하는 편이 현실적이다. 기억의 대체·삭제·검증 완료 승격은 의미 점수만으로 결정할 수 없다.

## 판단 종류별 기대 효용

다음 평가는 구현 구조와 기존 사례에서 도출한 가설이다. 실측 순위가 아니다.

| 판단 | 모델의 기대 역할 | 프로그램이 확인할 부분 |
| --- | --- | --- |
| 같은 ID·버전·경로인지, 날짜 순서가 어떤지 | 추가 이점이 작다. 명시된 값은 코드 비교가 더 직접적이다. | ID와 버전 일치, 날짜 계산, 출처 존재 |
| 표현이 다른 두 문장이 같은 교훈을 담는지 | 의미 중복 후보를 찾는 데 유망하다. | 공통 주장 외에 사라질 조건·근거가 있는지 |
| 일부는 겹치고 일부는 새 내용인지 | 부분 중복과 보완을 함께 표시하는 데 유망하다. | 고유 내용과 출처 보존 |
| 겉으로 반대인 두 기억이 실제로 충돌하는지 | 역할·시점·예외 조건이 입력에 있으면 보조할 수 있다. | 같은 대상과 적용 범위가 겹치는지, 조건 누락 여부 |
| 어떤 기억을 먼저 검토하거나 전달할지 | 검색된 후보의 순위를 매기는 데 쓸 수 있다. | 후보 검색의 누락, 전달 예산, 필수 기억 |
| 새 기록이 옛 기록을 대체하는지 | 대체 가능성과 방향을 제안할 수 있다. | 권한 있는 지시, 유효 시점, 적용 범위, 대상 버전 |
| 내용이 사실인지, 충분히 검증됐는지 | 제공된 근거와의 부합 여부를 보조할 수 있다. | 실제 실행·독립 검증 근거와 확인 수준 |

역할이 이미 구조화돼 있으면 부모·자식 구분에 모델을 쓸 필요가 적다. 모델의 이점은 자연어 속에 흩어진 역할·조건을 해석하거나 다른 표현의 주장을 대응시키는 데 있다. 추출한 역할도 처음에는 후보이며 원문과 연결해야 한다.

## 기존 기억 사례에서 기대하는 동작

[실제 관계 사례](RELATION_CASES_CODEX.md)의 기대 결과는 연구자가 제안한 값이며 모델 출력이나 독립 검토된 학습 정답이 아니다.

1. “역할과 작업대 경로를 확인하고 파일 명령에 명시”와 “역할·경로·현재 과제·메모 진입점을 대조”는 일부가 겹치고 일부는 보완한다. 완전 중복으로 합치면 고유한 지침이 사라진다.
2. 부모 rsch와 자식 rsch_sub_memory의 서로 다른 작업대는 역할별로 공존한다. 같은 역할·같은 용도·겹치는 유효 기간의 유일한 경로 두 개로 바꾸면 충돌 후보다. 역할이 빠지면 판정을 보류한다.
3. 과거 “조사 전”과 이후 “조사 착수”는 시간에 따른 상태 변화일 수 있다. 새 연구 지시만 있고 수행 근거가 없다면 “조사 완료”로 올릴 수 없다.

“중복 / 보완 / 충돌 / 대체” 하나를 반드시 고르는 문제로 만들면 사례 1을 제대로 표현하기 어렵다. 다음처럼 질문을 나누는 설계가 더 적합하다.

- 같은 대상과 주제를 말하는가?
- 적용 역할·시점·조건이 겹치는가, 구분되는가, 알 수 없는가?
- 공통 주장과 각 기억에만 있는 주장이 있는가?
- 겹치는 조건 아래 두 주장이 함께 성립할 수 있는가?
- 현재 판단에 필요한 조건이나 근거가 부족한가?

대체는 이 결과와 별도로 방향·권한·유효 시점·수행 근거를 확인한다. 여러 질문의 출력이 서로 모순될 수 있으므로 결합 규칙도 필요하다. 단일 질문의 softmax를 여러 독립 관계의 확률처럼 해석하지 않는다.

## 공개 후보의 차이

| 후보와 직접 근거 | 확인한 구조와 평가 범위 | 이번 연구에서의 위치 |
| --- | --- | --- |
| [TypeSafe Jev](https://typesafe.ai/blog/introducing-system-one-models-and-jev) | 상업용 원 모델. 형식이 정해진 확률적 판단과 여러 질문 처리를 제공한다. 소개 평가 일부는 다른 모델의 판단을 기준으로 한다. | 개념·API 비교 대상. 출력 형식 보장은 의미 정답 보장과 다르며 한국어 기억 성능은 별도다. |
| [vinnylarouge/jevlike](https://github.com/vinnylarouge/jevlike/blob/94f5fd1b0b11d52bbdfdf4e0ee6aa96b568f8452/README.md) | 문맥·가변 선택지를 점수화하는 독립 연구용 구현. 기본은 처음부터 학습하는 byte 모델이고, 동결한 사전학습 encoder를 쓰는 경로도 있다. 공개 실험은 합성 선택 및 Wikispeedia 다음 클릭이다. | 판정 구조 연구와 별도 학습 후보. 원 Jev의 학습 결과나 기억 이해 능력을 재현했다고 볼 수 없다. |
| [Kev](https://github.com/jaredpalmer/kev) | 읽은 버전은 Kev 1.0의 0.8B·4B·9B·27B. 공개 가중치, 선택·이진·점수 질문, 추가 학습 경로와 출처를 나눈 평가를 제공한다. | 바로 평가할 후보로 더 구체적이다. 우리 데이터에서 보정·보류 기준과 처리 가능 비율을 확인한다. |
| [daseinlabs/open-jev](https://github.com/daseinlabs/open-jev) | 기본은 Gemma 3 4B에서 후보 문자열의 이어질 가능성을 점수화한다. 과제별 학습 head 경로도 있다. README는 기본 확률이 보정된 판단 확률이 아니라고 명시한다. | 생성 없이 후보를 점수화하는 비교군. 이름이 비슷한 NLI 모델과 혼동하지 않는다. 학습 head 경로는 현재 MLX 기반이다. |
| [NanoJev](https://github.com/TianyuCodings/NanoJev) | 0.6B 병렬 판단 모델과 게임 중심 자료·평가를 공개한다. | 고정 형식 판단의 구현 참고. 게임 평가를 기억 관계 성능으로 이전하지 않는다. |
| [mDeBERTa NLI](https://huggingface.co/MoritzLaurer/mDeBERTa-v3-base-mnli-xnli) | 두 문장의 함의·모순·중립을 분류하는 학습 모델. 다국어 사전학습과 MNLI·XNLI 학습, 15개 XNLI 언어의 평가를 제공한다. 제시된 평가에는 한국어가 없다. | 가벼운 의미 관계 기준선. 한국어 기억에서 직접 비교해야 한다. |

영어 NLI 기준선으로 [nli-deberta-v3-base](https://huggingface.co/cross-encoder/nli-deberta-v3-base)도 확인했다. NLI의 중립은 곧 무관함을 뜻하지 않으며, 함의는 방향성이 있다. A가 B를 함의한다고 해서 두 기억 전체가 동등하지 않다. 양방향 함의 점수가 높아도 적용 조건과 근거를 보존할 병합 규칙은 별도로 필요하다.

Kev README는 선택지 순서에 따라 답이 바뀔 수 있고, 확률 보정이 정답 자체를 바꾸지는 않는다고 명시한다. 일반 공개 평가의 허용 오류 5%에서 Kev 4B·9B·27B가 처리하는 비율은 0.52~0.69로 보고한다. 이는 저자의 해당 평가 결과이며 우리 기억의 자동화율이나 허용 오류 기준이 아니다. 같은 페이지의 개발·시험 점수와 Jev의 개발 점수를 혼합해서 순위를 만들지 않는다.

## 입력과 점수의 실패 조건

[첫 입력 초안](JEVLIKE_CASE_01_DRAFT.json)은 UTF-8 333바이트다. vinnylarouge/jevlike의 기본 문맥 192바이트에서 자르면 자식 역할이 사라진다. 이는 해당 기본 구현과 우리 입력의 실제 불일치이며 Jev 계열 전체의 길이 한도는 아니다. 기본 선택지 32바이트도 별도로 확인해야 한다. 길이 설정을 늘리는 것만으로 학습된 모델의 품질이 유지된다고 가정하지 않는다.

[model.py](https://github.com/vinnylarouge/jevlike/blob/94f5fd1b0b11d52bbdfdf4e0ee6aa96b568f8452/jevlike/model.py)의 softmax 값은 제시된 선택지 사이의 상대 점수다. 정답 선택지가 빠져도 높은 값의 승자가 나올 수 있다. 0.95 출력이 곧 우리 기억에서 95% 맞는다는 뜻은 아니다. 선택지 순서, 표현 길이, “해당 없음”, 근거 부족 입력에서 검증해야 한다.

같은 README의 약 100배 속도 비교는 작은 생성 모델이 400토큰을 쓰게 한 설정이다. 기억 관계 이름 몇 개만 출력하는 일반 LLM이나 NLI 기준선에 같은 배수를 적용할 수 없다. 후보 생성, 입력 준비, 첫 호출·캐시, 불확실한 건의 재검토까지 포함해 측정한다.

## 제안하는 처리 흐름과 통제 지점

1. 검색·명시적 관계로 비교할 기억 쌍을 줄인다. 모든 기억 쌍을 매번 비교하지 않는다. 필요한 후보를 찾지 못하면 작은 모델도 복구할 수 없다.
2. 코드가 ID·버전·명시된 역할·시점을 확인하고, 모델 입력에 주장과 필요한 조건이 보존됐는지 검사한다.
3. 판단 모델이 의미 관계와 정보 부족 여부를 평가한다. 원문 ID·버전과 모델·질문 설정을 결과에 연결한다.
4. 검증된 범위의 가벼운 분류·검토 순위 조정에 결과를 쓴다. 불확실하거나 병합·대체의 영향이 큰 건은 일반 LLM 또는 지정된 검토 주체로 보낸다.
5. 기억 관리부가 변경 정책·권한·현재 버전과 근거를 확인한 뒤 확정한다. 원본을 보존하고, 확정된 관계·원문 변경에 따라 그래프와 파생 view를 갱신한다.

모델은 관계 후보를 제안하고 그래프는 관계·출처·변경 영향을 기록한다. 둘 중 하나의 도입으로 다른 쪽의 정확성이나 갱신 책임이 해결되지 않는다. 보류된 건은 임의로 승자를 골라 삭제하지 않으며, 검색·기존 기억을 이용하는 경로와 검토 상태를 유지한다.

## 같은 기억 사례로 비교할 평가

먼저 기존 세 사례와 변형을 바탕으로 한국어 평가 묶음을 만든다. 독립 검토로 기대 관계·보존할 조건·근거를 확인하고, 불일치 자체도 기록한다. 같은 원문에서 만든 표현 변형이나 인접 기록이 학습과 시험 양쪽에 섞이지 않도록 묶음 단위로 나누고, 뒤에 생긴 기억으로 시간 순서 검증을 둔다. 현재 여섯 사례만으로 도입 결론을 내리지 않는다.

비교군은 규칙·검색만, 학습된 NLI, 짧은 구조화 출력을 쓰는 일반 LLM, 학습된 Kev 등 판단 모델이다. 처음부터 학습하는 Jevlike는 충분한 라벨과 앞선 비교 결과가 있을 때 추가한다. 역할·시점 등 코드가 아는 조건을 모든 비교군에 동일하게 제공한다.

| 평가 관점 | 기록할 값과 시험 |
| --- | --- |
| 관계 분류 | 관계별 정밀도·재현율, 부분 중복과 보완의 동시 표현, 함의 방향 |
| 중요한 오류 | 서로 다른 기억의 잘못된 병합 후보, 실제 충돌 누락, 근거 없는 대체·완료 승격을 별도 집계 |
| 보류의 효용 | 검증용 자료에서 고른 오류 기준에 따른 처리 비율, 보류율, 보류 건 검토량. 시험 자료로 기준을 조정하지 않음 |
| 점수 신뢰성 | ECE·Brier 등 보정과 확신한 오답. 관계별·길이별·한국어 표현별로 분리 |
| 입력 민감성 | 역할·시점 제거, 예외·부정 추가, A/B 순서 교환, 선택지 순서 변경, 무관 후보 추가, 정답 후보 제외, 긴 문맥 절단 |
| 후보 검색 | 필요한 기억 쌍의 회수율. 분류기가 받은 쌍만으로 전체 누락을 평가하지 않음 |
| 실제 비용 | 전체 처리 시간, 첫 호출과 재사용, 큰 LLM 호출 수, 검토 시간, 라벨·학습·배포 유지 비용 |
| 다음 업무 효과 | 동일 실패 재발, 사용자 정정, 불필요한 검색·재작업, 조건 손실 |

모든 판정을 큰 LLM이 맡는 기준선과 비교할 때 대략적인 비용 구조는 작은 모델 비용 + 보류 비율 × 상위 검토 비용 + 학습·운영 비용의 배분이다. 이 합이 작고 중요한 오류가 증가하지 않아야 이점이 있다. 이것은 비용 구조이며 수익이나 절감률의 실측 결과가 아니다.

## 요구사항에 반영할 제안

- M02: 중복·보완·충돌·대체를 하나의 강제 선택으로만 표현하지 않는다. 범위 비교, 방향, 정보 부족과 다중 관계를 지원한다.
- M03: 입력·후보 보존과 한국어 평가를 선행 조건으로 둔다. 점수의 기준과 후보 검색 범위를 기록한다.
- M04: 의미 분류와 승인된 기억 변경을 분리한다. 모델 점수만으로 삭제·대체·확인 수준 승격을 하지 않는다.
- M06: 선택한 오류 수준에서의 처리 비율과 실제 호출·검토·재작업 감소를 평가한다. 모델 크기나 공개 정확도를 도입 효과로 대신하지 않는다.
