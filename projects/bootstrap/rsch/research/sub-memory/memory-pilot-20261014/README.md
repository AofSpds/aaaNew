# 기억 관계 첫 시험과 데이터 수집

이 폴더는 한국어 기억 18쌍으로 규칙 기준선과 Kev 0.8B를 비교하는 탐색 시험이다. 실제 기록에서 구성한 3쌍과 통제 변형 15쌍을 구분한다. 기대 판정은 Codex가 제안한 값이며 사용자 또는 별도 검토가 끝나기 전에는 정답으로 취급하지 않는다.

## 보관 구조

- collection/cases.jsonl: 계속 추가할 기억 쌍. 원문 위치·버전·발췌·변형 내용과 입력 해시를 보존한다.
- collection/annotations.jsonl: 기대 판정과 검토 기록. 이전 판정을 덮어쓰지 않고 supersedes로 새 검토를 연결한다.
- data/: 모델 실행 전에 고정한 v1 입력·기대 판정·질문·해시. 이번 실험 재현용이므로 수정하지 않는다.
- runs/: 실행마다 입력 복사본·실제 요청·응답·모델 버전·평가를 별도로 보존한다.
- vendor/kev/: 커밋 0a6d3fafeee7f3f76a9a4a522bf8b9d5b50bd7e5의 추론 소스. 외부 소스를 수정하지 않는다.
- .venv/ 및 .cache/: 이 실험만을 위한 라이브러리와 공개 가중치 캐시.

두 질문은 내용 겹침과 조건을 고려한 양립 가능성이다. 부분 중복을 완전 중복과 구분하며, 양립 가능에는 다른 역할·시점의 공존도 포함한다. 기억의 삭제나 대체는 실행하지 않는다.

## 첫 실행

CPU float32, 스레드 4개로 Kev 0.8B를 실행한다. 로컬 GPU는 RTX 3050 Ti 4GB지만 이번에는 GPU 속도나 배포 성능을 측정하지 않는다. 공개 모델을 내려받으며 기억 입력은 외부 추론 서비스에 보내지 않는다.

질문과 입력만 모델에 전달하고 기대 판정·판정 이유는 제외한다. 18쌍의 기본 응답 후, 미리 지정한 6쌍에서 선택지 순서를 뒤집는다. 입력을 자동 절단하지 않으며 한도 초과는 오류로 처리한다. 학습이나 확률 보정은 수행하지 않는다.

보고서의 일치율은 검토 전 제안과 얼마나 맞는지 보여주는 탐색값이다. 3개 원문 묶음의 변형 18개는 독립적인 실제 사례 18개가 아니다. 이를 일반 정확도나 자동화 가능 비율로 해석하지 않는다. 쉬운 다수 범주만 고르는 기준선도 함께 기록한다.

## 사례를 추가하는 방법

collect.py는 현재 수집 파일에 추가만 한다. 같은 ID나 동일 입력 중복, 출처·입력 해시 불일치는 거부한다. 운영 서비스가 아닌 단일 작성자용 도구다.

1. 기존 사례와 같은 구조의 JSON 파일에 두 기억, 적용 맥락, 원문 발췌와 버전, 원문 묶음 group_id를 넣는다. 실제 기록은 observed_source_pair, 의도적으로 바꾼 예시는 controlled_variant로 표시한다.
2. collect.py add-case --file 사례.json으로 추가한다. 새 사례는 exploratory 상태로 시작한다.
3. 기대 판정은 별도 JSON으로 collect.py add-annotation --file 판정.json에 기록한다. 작성자·이유·입력 해시를 넣고, 검토 전에는 proposed로 둔다.
4. 사용자 또는 별도 검토가 있으면 새 annotation_id를 발급하고 기존 판정 ID를 supersedes로 연결한다. 검토 응답의 원문·날짜도 보존한다. 모델 예측만으로 reviewed 상태로 올리지 않는다.
5. collect.py validate로 수집 구조를 확인한다. --check-current-sources 옵션은 현재 원문과 비교하므로 원문이 나중에 바뀌면 과거 기록도 변경 감지 대상으로 보고한다. 과거 원문 해시를 현재 값으로 덮어쓰지 않는다.

다음 실험은 collection에서 새 스냅샷을 만들어 별도 버전으로 고정해야 한다. v1 파일이나 실행 결과를 덮어쓰지 않는다. 학습·평가를 나눌 때 같은 원문에서 나온 변형은 한 묶음으로 유지한다.

사용자 정정, 실제 충돌, 역할 차이로 공존한 사례, 보류 후 해결된 사례를 우선 수집한다. 입력과 기대 판정뿐 아니라 모델이 틀린 이유와 최종 처리 결과를 연결해야 학습에 쓸 근거가 된다.
