## 1. 역할 트리

```text
Owner (한알)   + IVA              결정·종료. Owner의 검증자 = IVA
├─ AAA DPM      + DPMV             aaa 도메인 + 전체 총괄 (domains 장부·CORE)
└─ DPM          + DPMV             도메인 하나 (domains/<도메인>/ 기록은 AAA DPM과 합의)
   └─ PLN       + PLNV             프로젝트 하나 — 기획
      ├─ RSCH   + RSCHV            연구·시험 (PLN 아래에서 지원)
      └─ ARCH   + ARCHV            설계
         └─ PMO + PMOV             구현·코드·실행 (결과를 ARCH에 보냄)
```

위계 (Owner 2026-10-18): 단계는 일의 종류이고 위계가 있다 — "네 일의 종류입니다. 위계는 있습니다." / 위 모양 확인 "네 맞습니다". RHS #7(PLN 아래 PMO/RSCH 나란히)·#12(ARCH는 PLN 밑)에서 PMO를 ARCH 아래로 내린 것.

V(검증자)는 모두 비상설. 필요할 때 열고 판정만 남긴다.

## 2.1 검증 규칙 (Owner 2026-10-18)

- 검증은 **다른 역할에 넘길 때 한 번** 한다. 예: PMO가 작업을 끝내고 ARCH에 보낼 때 PMOV가 본다.
- 목적: "검증 지옥"(작은 단계마다 검증을 거는 것)을 피한다.
- V는 짝의 상위가 열고, 판정만 남기고 닫는다.
- 워크플로 칸(CORE 3)으로 넘길 것: 예시에서 PMO 결과는 ARCH로 간다(설계 대조). 넘김 경로 전체는 워크플로에서 정한다.

## 2.2 역할 단위 강제 (Owner 2026-10-18, R3)

- 권한·쓰기 범위·기억 뷰의 단위는 **역할**이다. 세션은 역할에 맞춰 어디서든(Claude Code, Codex, 그 밖) 열 수 있다 (RHS #18과 같은 뜻).
- 강제는 훅으로 한다: 세션이 어떤 역할인지 확인 → 그 역할의 쓰기 범위 밖이면 거부.
- 구현 전에 풀 것:
  1. 세션이 자기 역할을 어떻게 아는가 (실측: Claude는 cwd가 작업대를 정하고 훅은 cwd의 `.claude`만 읽음 → 역할 폴더에서 열면 역할이 정해짐. 작업대가 로컬 저장소일 때의 자리는 MEM_STRG와 맞출 것)
  2. Codex 훅으로 같은 거부가 되는가 — **미실측** (PreToolUse deny, Stop block)
  3. 역할 → 쓰기 범위 표는 CORE에 한 곳, 실행기마다 어댑터가 읽음 (`apps/`)

## 2.3 세션 이름 (Owner 2026-10-18, R4)

```text
<도메인>/<프로젝트>/<역할>      대문자 · 칸 사이 "/" · 칸 안 "_"
<도메인>/<역할>                 도메인 단위 역할 (DPM)
도메인 이름 = AAA_NEW (한 칸)
예: AAA_NEW/DPM · AAA_NEW/BTSR/PLN · AAA_NEW/BTSR/RSCH · AAA_NEW/MEM_STRG/RSCH
```

## 3. 역할마다 가지는 것 (기억 모델과 연결)

- 역할 Current 한 장 — README 같은 것, 모듈화된 메모리 뷰 (이 세션 F1-c, 2026-10-18)
- 로드맵 — 자기 범위 (#32)
- 작업대 — 로컬 저장소, 백업 (F1-b)
- 쓰는 곳 — 자기 역할 폴더만. 코드는 PMO만 (#14)
