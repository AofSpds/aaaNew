## 0. 전제 (Owner 결정, 2026-10-18)

- 사람 개발팀처럼 일합니다. 작업 단위마다 Git 브랜치를 땁니다.
- 역할별로 모은 자료(메모·시험 자료·산출물)는 **그대로** 자료 저장소에 보관합니다. Git에는 참조값만 둡니다.
- PR은 그 프로젝트를 주관하는 PLN이 DPM 승인을 받아 머지합니다. 머지된 main이 도메인 CURRENT이고, Owner가 최종 확인합니다.
- 자료는 작업 브랜치 단위로 묶고, PR 머지 때 고정해 아카이브로 보냅니다.

## 1. 묶음과 참조값

- **묶음** = `work/<브랜치>/` 아래의 역할별 폴더 전체 (`<역할>/` 단위로 나뉨)
- **manifest** = 묶음 안의 파일마다 `상대경로 ⇥ 크기 ⇥ sha256` 한 줄
  - 경로순으로 정렬하고, UTF-8·LF로 씁니다.
  - 이 채널의 자체 규칙입니다. RFC 8785 JCS가 아닙니다.
- **참조값** = PR 본문에 넣는 짧은 블록입니다. 실측 예:

```text
format: MEMSTORE_REF v1
store_id: <논리 저장소 ID>
bundle_id: <도메인>/<프로젝트>/<브랜치>@<브랜치 head 커밋 7자>
sealed_by: <PLN 세션 이름>
source_commit: <브랜치 head 커밋 40자>
roles: pln, pmo, rsch
files: 21
bytes: 336837
manifest_sha256: <manifest 파일 바이트의 sha256>
backup: <백업 위치 ID — 실제 경로는 기기 설정에서 찾음>
```

- 머지 커밋의 해시는 참조값에 넣지 **않습니다**. 넣으면 자기 자신을 가리키는 순환이 생깁니다(Pro P2 지적).
  - 대신 머지한 뒤 `archive/INDEX`에 "머지 커밋 → bundle_id" 한 줄을 추가합니다.

## 2. PR 때 고정 절차 (PLN)

1. 그 브랜치 묶음에 대한 새 쓰기를 막습니다(쓰기 CLI가 거부).
2. manifest를 만들고 지문을 계산합니다.
3. `archive/<프로젝트>/<브랜치>@<head7>/`에 봉인 사본을 만들고 읽기 전용으로 표시합니다.
4. 봉인 사본을 다시 읽어 manifest와 대조합니다.
5. 백업 위치로 복사하고 다시 대조합니다. **실물을 먼저 저장합니다.**
6. PR 본문에 참조값 블록을 적습니다. **참조는 나중에 남깁니다.**
7. DPM 승인 → PLN 머지 → `archive/INDEX`에 머지 커밋 한 줄 → Owner 확인 표시

## 3. 복원 절차

1. Git의 PR이나 머지 커밋에서 참조값 블록을 읽습니다.
2. 백업 위치에서 bundle_id 묶음을 찾습니다.
3. **빈 새 폴더**에 복사합니다. 기존 자료를 덮어쓰지 않습니다.
4. 대조합니다.
   - manifest 지문이 참조값과 같은지
   - 파일마다 크기와 지문
   - 빠진 파일, 목록에 없는 파일
5. 결과는 "완전 일치" 또는 "불일치 목록"입니다.

- 시험 묶음: 역할 3개(pln·pmo·rsch), 파일 21개, 336,837바이트
  - 역할마다 메모 일지 200줄, 노트 1개, 시험 자료 5개
- 봉인(manifest + 봉인 사본 + 백업 사본, 각각 대조): 0.37초. 봉인 사본과 백업 사본 모두 완전 일치
- 참조값만 보고 빈 폴더에 복원: 0.02초, 완전 일치
- 일부러 넣은 고장 5가지 결과 (모두 잡힘):

| 고장 | 잡혔나 | 대조 결과 |
| --- | --- | --- |
| 시험 자료 1바이트 변경 | 잡힘 | 내용 다름: rsch/test-data/sample_2.bin |
| 파일 하나 빠짐 | 잡힘 | 누락: pln/notes.md |

- 한계:
  - 시험 자료가 작습니다.
  - 백업이 같은 디스크에 있어서 디스크 고장 대비는 확인하지 않았습니다.
  - 쓰는 도중 봉인하는 경우(잠금 경쟁)와 전원 장애도 시험하지 않았습니다.
  - 실제 Git PR과 연결하는 부분도 시험하지 않았습니다.
  - "읽기 전용 표시"는 실수 방지일 뿐 보안 장치가 아닙니다.

## 5. 남은 것

- **백업 실물을 어디에 둘지**(Owner 결정 D-a): 다른 디스크, 외장 디스크, 별도 로컬 Git 등
- 봉인하는 순간 진행 중인 쓰기를 어떻게 끝낼지: 잠금을 잡고 진행 중인 쓰기가 끝나기를 기다린 뒤 봉인
- 큰 시험 자료(수백 MB 이상)의 봉인 시간과 백업 공간
- PR이 오래 열려 있을 때 그 사이 자료의 보호(PR 사이 손실 구간)
- 머지가 취소·되돌려진 PR의 봉인 묶음 처리 (지우지 않고 "머지 안 됨" 표시)

## 6. Pro 검토에 물을 것

1. 이 참조값 블록과 manifest 규칙에 빠진 칸이나 위험이 있는가

4. 외부 서비스 없이 쓸 수 있는 백업 실물 위치의 선택지와 각각의 위험
