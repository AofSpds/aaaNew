## 1. 무엇을 만드는가
Owner가 운영하는 여러 도메인이 공통으로 쓸 "에이전트 메모 로컬 저장소"와 그 저장소를 관리하는 "엔진". 이 의뢰는 그 저장소를 날마다 운영하는 방법(아카이브, Git 참조·백업·복원, 여러 기기, 모바일 열람, 기존 메모 이전)을 조사한다.

## 2. 사용 환경과 고정 제약
- Windows 11 PC(HANAL). 같은 PC에서 Claude Desktop 세션 여러 개와 Codex 세션이 동시에 쓴다. 다른 기기 jwDev가 있고, 그쪽 `C:\Users\<user>\dev`는 Google Drive 미러로 보고됐다.
- 역할마다 CURRENT(덮어씀), ROADMAP, ARCHIVE. 역할 → 도메인 롤업.
- Git에는 참조값만. 메모는 로컬 저장소. 외부 서비스 지양. PR마다 Git에 백업. 아무것도 지우지 않음. 키·시크릿 금지.
- Owner는 모바일에서 세션 이름만 볼 수 있다. 도메인 CURRENT를 모바일에서 볼 방법이 필요하다.
- 세션 권한(문서 확인):
  · Claude Code는 작업 폴더나 additionalDirectories 밖에 쓰면 승인을 요청한다.
  · Codex workspace-write는 작업 공간 밖에 쓰면 승인이 필요하다(writable_roots로 넓힘).
  · 그래서 저장소를 어디에 두느냐가 권한 문제와 바로 묶인다.
- 임시 저장 구조(우리 실측):
  · 역할별 jsonl 추가 전용 스트림 + 스트림마다 잠금 파일 + 쓰기 CLI 하나
  · SQLite는 재생성 캐시, 생성 Markdown view
  · Git 백업은 jsonl 추가 줄만(+2,000/−0 per 2,000건)
  · SQLite 파일을 Git에 넣으면 바이너리이고, WAL은 백업 전에 checkpoint가 필요하다

## 3. 질문
Q1. 아카이브: 원장이 이미 모든 판을 보존할 때, "아카이브"를 무엇으로 정의할지.
    · 갱신마다 / 상태가 바뀔 때 / 하루 1회 / 작업 단위가 닫힐 때
    · 이름 규칙, 목록(INDEX) 형식
    · 도메인 아카이브와 역할 아카이브의 관계
    · 선행 사례가 있으면 함께 든다(이벤트 소싱 스냅샷, 시계열 다운샘플링 등)
Q2. Git 참조값: Git에 무엇을 남길지.
    · 후보: 스트림 순번, 내용 digest, Merkle 루트, 스냅샷 파일
    · PR마다 백업하는 구체 절차
    · 복원 절차와, 복원이 맞는지 검증하는 방법
    · 비교 대상: git-annex, DVC, restic/borg(로컬 대상), SQLite VACUUM INTO/backup API, Litestream(로컬 대상), 그냥 jsonl 사본 커밋
    · `.gitattributes merge=union`의 위험
Q3. 여러 기기: 같은 저장소를 HANAL과 jwDev에서 쓸 때.
    · Google Drive 미러 위에 jsonl·잠금 파일·SQLite를 두면 생기는 위험과 근거
    · 대안 비교: 저장소를 미러 밖에 두고 Git으로 동기화, Syncthing 같은 P2P(외부 서비스로 볼지 포함), 기기별 스트림 + 병합, CRDT식 추가 전용 병합
    · 기기 ID를 봉투에 넣는 방법
Q4. 저장소 위치와 권한: 위 세션 권한 제약 아래에서 저장소를 어디에 둘지.
    · 저장소마다 Git 제외 폴더 / 고정 경로 1곳 / 세션 작업 폴더 안의 링크 등
    · 비교할 위험: git worktree 사본이 많을 때 저장소가 갈라지는 위험, 승인 요청 빈도, 설정 변경 필요 여부
Q5. 모바일 열람: 외부 서비스 없이(또는 최소한으로) Owner가 휴대폰에서 도메인 CURRENT를 볼 방법.
    · 후보: 생성 view를 Git에 올려 GitHub 앱으로 보기, 같은 망 안의 로컬 웹 서버, 세션 이름에 상태를 싣기, 그 밖의 방법
    · 각 후보의 보안·시크릿 노출 위험
Q6. 기존 메모 이전: 여러 도메인 저장소의 Git 안에 이미 있는 CURRENT·WORKLOG·메모를 로컬 저장소로 옮기는 절차.
    · Git 이력은 보존하고 아무것도 지우지 않는다
    · 단방향 가져오기, 원본에 "옮겨짐" 표시, 이전한 뒤 Git 쪽에 남길 참조값
    · 도메인별 대상 목록을 만드는 양식
