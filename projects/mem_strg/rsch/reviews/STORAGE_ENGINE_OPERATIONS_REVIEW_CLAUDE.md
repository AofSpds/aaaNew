## 1. 결론

- 임시안 B(jsonl 원장 + SQLite 투영 + 생성 view)는 **비교 기준선으로 유지**합니다. 확정안은 아닙니다.
- 검증 순서를 바꿉니다. 지금까지는 속도와 손실을 쟀습니다. 다음은 **확정·충돌·복원**을 잽니다. 두 답변이 같은 결론을 냈습니다.
- 그래프 DB는 지금 채택할 근거가 없습니다. 이름 붙은 작업(출처 설명, 영향 계산)에서 이득이 보일 때 **투영 후보**로 비교합니다. 정본으로 두지 않습니다.
- JEV-like는 로컬 대안으로 좁은 판정을 할 수 있습니다. 판정은 **제안 사건**으로만 남기고, 확정 변경은 별도 사건으로 둡니다.

## 3. 채택 — 설계 방향에 넣을 것 [Pro 제안, 설계 결정 아님]

1. **기록 봉투**: 공통 칸 + 사건 종류별 부속(P1 Q1 표)
   - 새로 넣을 칸: `event_id`와 `subject_id` 분리, `command_id`(재시도 중복 방지), `expected_revision`, `writer/device/epoch`, digest 규칙 명시, `recorded_at`과 `valid_from` 구분
2. **추적 두 가지를 나눔**: 출처 설명은 범위를 제한해도 되지만, 무효화는 누락하면 안 됩니다.
   - "부재에 대한 의존"(예: 역할 등록부 revision)도 의존성에 넣습니다.
   - 다 따라가지 못하면 dirty/pending으로 남기고, 게시하기 직전에 generation을 검사합니다.
3. **아카이브의 정의**: 원장이 이미 모든 판을 보존하므로, 아카이브는 **이력에 이름과 업무 의미를 붙이는 것**입니다.
   - 후보: 작업 종료 + 일일 도메인 + 상태 전환
   - 도메인 아카이브는 역할별 revision 목록을 고정합니다. 사본을 만들지 않습니다.
4. **보장 경계 4개**: 저장 성공 / 기록 유효 / CURRENT 반영 / 백업 완료. 각 경계에서 무엇을 약속하는지 먼저 정의합니다.
5. **백업**
   - 실물을 먼저 저장하고, 참조는 나중에 Git에 남깁니다.
   - 복원은 새 폴더에서, `as_of`를 고정해 재생성하고 비교합니다.
   - 복원된 기기는 새 writer epoch를 씁니다.
6. **여러 기기**: 두 사본 사이에는 잠금이 공유되지 않습니다. 둘 중 하나를 고릅니다.
   - 역할×기기×epoch로 스트림을 나누고 완성된 segment만 전송
   - 주 작성 기기 1대
7. **위치**
   - checkout과 Drive 미러 밖의 고정 경로에 두고, 쓸 때 `store_id`를 확인합니다.
   - 경로가 없으면 조용히 새로 만들지 않습니다.
   - 링크로 권한을 우회하지 않습니다.
8. **모바일**
   - `generated_at`과 `data_as_of`를 나눠 표시합니다.
   - 원장이 아니라 허용한 칸으로 만든 export만 넘깁니다.
9. **검색**: SQLite FTS5를 기준선으로 둡니다.
   - 한국어 주의: trigram은 3글자 미만을 찾지 못합니다.
   - 임베딩(예: multilingual-e5-small)은 FTS가 실패한 질문을 모은 뒤 비교합니다.
10. **로컬 판정**: 규칙·digest 대조군을 먼저 둡니다. 후보는 reranker, NLI, 4B 모델입니다. 판정 기록 칸은 P1 Q6 표를 따릅니다.
11. **그래프 투영 후보**: 질의 언어로 나눕니다.
    - Cypher → LadybugDB·RyuGraph
    - RDF/PROV → Oxigraph
    - SQL/PGQ → DuckPGQ (버전 조합 확인 먼저)
    - 세션마다 DB를 직접 열지 않고, 한 소유 프로세스를 둡니다.

## 4. Pro 답변의 한계

- 비용·적합성 표는 모두 [추정]입니다. HANAL에서 잰 값이 아닙니다.
- 제품 버전(예: LadybugDB 0.21.2, pyoxigraph 0.5.11, SQLite 3.54.1)과 날짜는 Pro 조회값입니다. 이 채널은 다시 확인하지 않았습니다.
- 처리 모델은 화면 표시("Pro")만 확인했습니다.
- P1 의뢰서에 우리 쪽 틀린 표현(70–80%)이 들어갔는데, Pro가 스스로 찾아 정정했습니다. 의뢰서 입력 자체를 다시 검토할 필요가 있다는 교훈입니다.
