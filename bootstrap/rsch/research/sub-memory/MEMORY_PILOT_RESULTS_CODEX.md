# 기억 관계 첫 실행 결과

작성: Codex, 2026-10-14 KST. 사용자 요청 “대략 테스트를 해보고 우리데이터를 쌓아 볼까요”에 따른 소규모 실행이다.

**Kev 0.8B를 한국어 기억에 실제로 실행했고, 이 모델과 현재 질문 형식으로는 자동 병합에 사용할 근거가 부족했다.** 실제 기록에서 만든 3쌍과 통제 변형 15쌍, 검토용 판정 18건, 모델 응답 24건을 저장했다. 잘못된 구별과 선택지 순서에 민감한 사례부터 검토 자료로 축적할 수 있다.

## 무엇을 실행했는가

[실험 폴더](memory-pilot-20261014/README.md)에 전용 가상환경과 공개 모델 캐시를 만들었다. CPU float32, 스레드 4개로 실행했으며 기억 입력을 외부 추론 서비스에 보내지 않았다. 로컬에 RTX 3050 Ti 4GB가 있지만 이번 수치는 GPU 측정이 아니다.

- 원문 묶음: 역할·경로 확인 교훈, 부모와 자식의 작업대, 조사 전후 상태.
- 데이터: 실제 기록을 맥락과 함께 재구성한 3쌍, 의도적으로 조건·표현을 바꾼 15쌍.
- 문항: 내용이 완전 중복·부분 중복·별개·판단 불가 중 어디인지, 두 기록이 양립·충돌·판단 불가 중 어디인지.
- 기본 실행: 18쌍 × 2문항 = 36판정.
- 선택지 순서 시험: 사전에 고른 6쌍 × 2문항 = 12판정.
- 추가 진단: 단순한 영어·한국어 문제 4개, 영어로 옮긴 기억 2쌍. 기본 성적과 합치지 않았다.
- 학습, 데이터에 맞춘 확률 보정, 기억 원본 병합·삭제는 하지 않았다.

기대 판정은 모델 실행 전에 고정한 Codex의 제안이다. 독립 검토된 정답은 아직 0건이다. 따라서 아래는 제안과의 일치 수이며 일반적인 정확도가 아니다. 3개 원문에서 파생한 변형을 독립적인 실제 사례 18건으로 세지 않는다.

## 첫 비교 결과

| 항목 | 명시 정보와 정확한 복사만 처리하는 규칙 | Kev 0.8B |
| --- | --- | --- |
| 기본 문항 | 36개 | 36개 |
| 결정한 문항 | 16개, 나머지 20개는 계산상 보류 | 36개 모두 최상위 선택지를 기록 |
| 기대 제안과 일치 | 결정한 16개가 모두 일치 | 17/36 |
| 두 문항이 모두 일치한 기억 쌍 | 8/18, 나머지는 보류 포함 | 3/18 |
| 내용 겹침 구별 | 명시 정보로 가능한 경우만 처리 | 5/18 |
| 양립·충돌 구별 | 명시 정보로 가능한 경우만 처리 | 12/18 |
| 선택지 역순 시 답 변화 | 해당 없음 | 3/12문항 |
| 사전 지정 p_max ≥ 0.8 | 확률을 출력하지 않음 | 0/36문항 |

규칙이 결정한 16개와 모델이 강제 선택한 36개는 처리 범위가 다르다. 일치 수 하나로 모델 우열을 정하지 않는다. 내용 구별에서 항상 다수 범주인 “별개”만 골라도 12/18이고, 양립 질문에서 항상 “양립”을 고르면 11/18이다. 이 값은 데이터 구성 확인을 위한 사후 기준선으로, 학습된 분류기 성능은 아니다.

원래 36개 모델 판정의 최대 p_max는 약 0.714였다. 사전 지정한 0.8을 적용하면 모두 검토로 보내게 된다. 이 작은 표본으로 0.8의 안전성을 검증한 것은 아니며, 현재 설정에서 상위 검토를 줄인 효과도 확인하지 못했다.

## 실제로 수집한 실패와 보류

- **부분 중복을 완전 중복으로 분류:** 역할·경로 확인은 공통이지만 “파일 명령에 경로 명시”와 “현재 과제·메모 진입점 확인”은 고유하다. L01을 완전 중복으로 골랐다.
- **다른 역할이나 용도의 기억을 완전 중복으로 분류:** P01·P05 등의 구체적 적용 대상을 제대로 구별하지 못했다.
- **반대 주장에 대한 문항 간 모순:** L04에서는 “확인해야 한다”와 “확인해서는 안 된다”를 완전 중복이라고 하면서, 양립 질문에는 충돌이라고 답했다. 여러 질문을 나눠도 결과 사이의 일관성 검사가 필요하다.
- **충돌 4개 중 1개를 충돌로 선택, 3개를 정보 부족으로 선택:** 나머지 3개를 양립 가능으로 고른 것은 아니다. 보류와 잘못된 허용을 구분한다.
- **완전 중복 오분류 후보 9개:** 검토 전 기대 제안을 기준으로 집계했다. 모델 결과만으로 병합했다면 고유한 조건이나 대상을 잃을 수 있는 후보들이다.
- **선택지 역순에 따른 변화 3개:** L01의 두 문항과 P01의 내용 겹침 문항이다.

모든 응답은 점수와 선택지 순서를 포함해 보존했다. 모델 예측을 새로운 정답으로 자동 편입하지 않았다.

## 추가 진단과 해석 범위

같은 로딩 경로에서 “문이 열려 있다 / 닫혀 있다”를 묻는 영어 2개와 한국어 2개는 4개 모두 맞혔다. 단순한 입력에 반응하지 않는 전면적 로딩 실패라는 설명은 약해진다. 이것만으로 구현 전체가 검증됐다는 뜻은 아니다.

L01과 L04를 영어로 옮긴 추가 4문항은 3개가 기대 제안과 일치했다. 부분 중복 L01은 여전히 틀렸다. 한국어만이 원인이라고 단정할 수 없고, 작은 모델의 과제 적합성·질문 정의·선택지 표현을 함께 살펴야 한다. 결과를 본 뒤 만든 작은 진단이므로 영어 성능 우위나 개선율을 추정하지 않는다.

기본 18쌍의 처리 중앙값은 약 2.95초, 합계 약 51.5초였다. 첫 모델 로딩은 다운로드를 포함해 약 98초였다. 최적화되지 않은 CPU 참조 경로의 관측값이며 GPU나 다른 모델 대비 속도 결론으로 쓰지 않는다. 문맥 길이는 48~205토큰이고 절단은 없었다.

## 우리 데이터가 쌓이는 위치

[수집 원장](memory-pilot-20261014/collection/cases.jsonl)에는 기억 쌍의 출처·원문 해시·발췌·적용 맥락·변형 이유·원문 묶음을 남긴다. [판정 기록](memory-pilot-20261014/collection/annotations.jsonl)은 제안·검토·이견 상태와 작성자·이유·이전 판정 연결을 분리한다. [모델 관측](memory-pilot-20261014/collection/observations.jsonl)은 정답이 아닌 실제 응답 24건이다.

[검토 묶음](memory-pilot-20261014/collection/review_packets.jsonl)에는 모델 답과 기대 판정을 제외한 입력·출처가 있다. 첫 사용자 검토로 L01의 관계를 질문했으며 보고서 작성 시 응답은 대기 중이다. 응답이 오면 원문을 보존하고 해당 문항의 새 판정 기록으로 연결한다.

[collect.py](memory-pilot-20261014/collect.py)는 신규 사례와 판정을 추가한다. 같은 ID·동일 입력 중복, 해시 불일치, 독립 검토 표시 없는 reviewed 승격을 거부하는 검사를 확인했다. 이 검사는 검토자의 실제 신원이나 판정 품질까지 보증하지 않는다. 자동 수집 서비스나 운영 저장소가 아닌 단일 작성자용 실험 도구다.

기존 데이터와 실행 결과는 고정한다. 이후 학습·평가를 나눌 때 동일 원문에서 나온 변형은 같은 분할에 둔다. 지금 자료만으로 학습하면 작은 사례 묶음에 맞춘 결과를 일반 성능으로 오해하기 쉽다.

## 다음 판단에 필요한 자료

우선 실제 업무에서 생긴 중복·보완·충돌·보류 해결 사례와 사용자 정정을 추가하고, 기존 판정 제안을 검토한다. 모델의 답이 아니라 최종 처리와 그 근거를 라벨로 쌓는다. 추가 비교에서는 검토된 같은 입력으로 NLI·일반 LLM·다른 크기의 판단 모델을 비교한다.

현재 결과는 Kev 0.8B의 이 질문 형식에 대한 초기 결과다. Jevlike 계열 전체를 기각하거나 한국어 모델 학습의 불가능성을 뜻하지 않는다. 당장 적용한다면 규칙이 처리할 명시 정보부터 처리하고, 의미 판단은 검토 후보로 보존하는 범위가 적절하다.
