## 이번 요구사항에 반영할 제안

1. **그래프의 대상과 관계 의미를 명시한다.** 기억·원자료·업무·역할·view를 연결하는 방식을 검토한다. 근거 관계, 적용 관계, 충돌·대체 관계, 계산 의존 관계를 구분한다. 표현 방식은 저장 제품과 별도로 평가한다.
2. **선별 경로를 설명할 수 있어야 한다.** 도메인이 자식의 현재 업무에서 출발해 필요한 기억 후보를 찾고, 적용 조건·검토 상태·유효한 버전을 확인한다. 선정 근거와 추가 원문 조회 경로를 남긴다. 부모에서 연결된 모든 자료를 자동으로 모델 입력에 넣지 않는다.
3. **관계의 의미에 맞춰 탐색한다.** 그래프에서 도달 가능하다는 사실을 관련성·사용 가능성·변경 권한으로 자동 승격하지 않는다. 간접 관계를 합성할 때는 관계 종류와 적용 조건을 확인한다.
4. **원자료와 view를 각각 버전 관리한다.** 변경 시 영향받는 기억·view·캐시를 찾고 현재 사용 가능한지 다시 판정한다. 관계 누락이나 재계산 실패가 있으면 결과를 최신 완료 상태로 표시하지 않는다. 선택적 재계산 가능 여부와 전체 보류 범위는 미결정이다.
5. **view가 남기거나 생략할 내용을 정한다.** 필요한 역할·조건·근거·검토 상태를 보존한다. 불필요한 상세는 줄일 수 있고 필요하면 원자료를 재조회한다. 앞선 jevlike 입력 절단 문제도 이 요구에서 다룬다.
6. **작은 비교 사례로 이득을 확인한다.** 같은 원자료에 대해 문서 목록·태그 방식과 관계를 따라가는 방식을 비교한다. 필요한 기억의 누락, 불필요한 포함, 선정 근거 추적, 변경 반영 범위, 전달량·비용을 관찰한다. 수치 기준과 제품 선택은 이후 결정한다.

jevlike는 관계 후보 판정이나 선택 후보 점수화에 쓸 수 있는지 계속 연구한다. 관계의 저장·조회·검토·변경 반영이 같은 책임이라고 가정하지 않는다. Byul의 관계/view 연구와 jevlike의 적합성을 연결하는 작업이 남아 있다.
